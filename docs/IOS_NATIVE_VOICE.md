# Native iOS duplex voice backend

**The complete unsigned Unity iOS app now compiles and links; device behavior is unverified.** [Full-app CI run 34786581140](https://github.com/jethac/lucid-loop/actions/runs/34786581140), export commit `9744abc`, used Xcode 16.4 (16F6), iOS SDK 18.5, arm64 and an iOS 17 deployment target. This includes the plugin connected through `EncounterVoiceController` and `IosNativeVoiceAudio`. Signing, AVAudioEngine behavior, echo reduction and hardware latency remain separate checks.

## ABI

`Unity/Assets/Gyms/Plugins/iOS/LLVoice.h` is authoritative. Use Cdecl `__Internal` imports behind the iOS player platform guard. Every call must originate on the same Unity main thread. Caller buffers are never retained. Both directions use mono float32 at **24,000 Hz**, finite samples within [-1,1].

| Function | Contract |
| --- | --- |
| `int LLVoice_Start()` | Requires already-granted microphone permission. Returns 1 or a negative error. Capture starts disabled. Replaces prior backend and resets counters. |
| `void LLVoice_Stop()` | Main-thread teardown, safe when stopped. Restores previous session category/mode/options without deactivating Unity's shared session. |
| `int LLVoice_SetCaptureEnabled(int enabled)` | Enables or mutes input; purges buffered capture, resets converter history, advances capture epoch. Returns 1 on success, 0 when stopped, or a negative error. |
| `int LLVoice_ReadCapture(float* destination, int capacity)` | Copies available samples, capped at 24,000 per call. Returns zero while muted/stopped/empty and a negative fixed error on invalidation or conversion failure. Discard the destination contents if the return is negative. Resampling occurs on this main-thread call. |
| `int LLVoice_WriteOutput(const float* samples, int count)` | Returns accepted prefix length or a negative fixed error; up to 131,072 per call. Caller must retain/retry a partial remainder or fail explicitly. Invalid samples invalidate the backend. |
| `uint64_t LLVoice_GetConsumedOutput()` | Actual 24k samples dequeued by the source node this start, excluding underrun zeros. **Not DAC presentation time.** |
| `int LLVoice_GetQueuedOutput()` | Samples in the output ring; excludes engine/device buffering. |
| `int LLVoice_GetStarved()` | Last render needed more samples than queued. Idle starvation is expected. |
| `int LLVoice_GetStatus()` | 0 stopped, 1 running, negative error/invalidation. Poll each Update; no teardown occurs inside this getter. |

Fixed errors: -1 permission required; -2 session failure; -3 voice processing failure; -4 unsupported format; -5 engine failure; -6 route changed; -7 interruption; -8 media services reset/lost; -9 engine configuration changed; -10 wrong thread; -11 invalid output samples; -12 capture overflow; -13 conversion failure; -14 input mute unavailable; -15 OS below iOS 17. Save the negative status before Stop clears it. Start, SetCaptureEnabled, ReadCapture, WriteOutput and GetStatus return -10 on the wrong thread. Void calls do nothing; counter/queue getters return zero.

## Controller lifecycle

Initial typed-only sessions use Unity playback. On an iOS player, explicit Mic enable requests permission and waits for relay readiness before starting native audio. The controller stops the Unity output clip, discards its queued speech, and resets the speech-animation generation before enabling native capture. This first switch can cut off already queued NPC speech. Later Mic toggles retain native playback. The plugin has no network, keys, permission prompt, or Unity Microphone calls.

Mic off calls SetCaptureEnabled(0) and replaces future capture packets with silence so Live frame progress continues. An upload already sent cannot be recalled. Native NPC playback remains active. **The iOS microphone privacy indicator may remain visible while the duplex engine runs with capture muted.** Leave stops native audio immediately and requests provider closure with the existing final-usage handshake.

The controller polls native status each Update. Negative status stops audio and requests conversation closure, with explicit Talk required to restart. There is no automatic restart after route, interruption, or media-service changes. Output is bounded to three seconds by the controller; a partial native write fails the stream instead of silently losing samples. Playback progress uses native dequeued samples after the switch. The plugin does not own provider sessions or final usage.

## Graph and callback safety

Start configures playAndRecord, voiceChat, defaultToSpeaker, and the iOS 17-compatible allowBluetooth HFP flag. It does not override the output port, prefer built-in input, or enable A2DP. Headphone/HFP routes remain eligible. Apple documents paired HFP input/output under [allowBluetooth](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/allowbluetooth).

While the engine is stopped, Start enables input-node voice processing, checks its state, disables bypass, and mutes input. Session voiceChat mode alone is not that switch. See Apple's [voice processing API](https://developer.apple.com/documentation/avfaudio/avaudioionode/setvoiceprocessingenabled(_:)) and [AVAudioEngine WWDC19 session](https://developer.apple.com/videos/play/wwdc2019/510/).

The capture tap uses the active input-node output format after enabling processing. Supported formats are float32, 1–8 channels, 8–192kHz, interleaved or planar. It downmixes into a hardware-rate mono SPSC ring. ReadCapture performs streaming AVAudioConverter conversion to 24k using reused buffers and input-ran-dry handling; see [TN3136](https://developer.apple.com/documentation/technotes/tn3136-avaudioconverter-performing-sample-rate-conversions). Other formats fail explicitly.

An AVAudioSourceNode feeds mono 24k samples through this same engine's mixer/output, allowing engine conversion to the active route. Underruns produce zeros. Native callback bodies contain no explicit allocation, locks, logging, networking, converter calls, or synchronous dispatch. Storage is fixed and atomics are checked at compile time for lock-free support. Framework internals still require device profiling. See Apple's [source render block contract](https://developer.apple.com/documentation/avfaudio/avaudiosourcenoderenderblock).

Mute uses [voiceProcessingInputMuted](https://developer.apple.com/documentation/avfaudio/avaudioinputnode/isvoiceprocessinginputmuted?language=objc), guarded by runtime selector availability. It also discards queued capture and converter history. Epoch and enabled state share one atomic control word. A tap reads that word once: it can only observe the old enabled epoch, the new disabled epoch, or the new enabled epoch, never old enabled paired with a new epoch. Old callbacks retain their old tag and are rejected after re-enable. Captured samples carry those tags, preventing old queued application data from reappearing. This is application-buffer protection, not a hardware privacy-indicator timing guarantee.

Capture capacity is 262,144 tagged hardware-rate samples: about 5.46 seconds at 48k. Output capacity is 131,072 samples: about 5.46 seconds at 24k. Capture overflow invalidates instead of silently losing speech. Pump smaller packets every Update.

Callbacks retain AudioState independently of the backend/engine owner and never capture the owner. Stop marks it inactive before removing observers, stopping the engine, removing the tap and releasing ownership. Observers are installed after the plugin constructs/prepares its graph, before engine start. The active format and route identity are rechecked after observer installation, catching changes during the earlier construction window. Graph attach/connect/prepare therefore cannot deterministically invalidate startup through the plugin's own observer. An internal starting state accepts invalidation; the final compare-exchange to running cannot overwrite a notification received during startup. This fails closed if hardware changes during setup. A route handler ignores only a delayed category-change notice when current category, mode, actual post-setup options, and ordered input/output UID plus port-type identity still match its captured setup. Any other route reason or mismatch invalidates. Engine-configuration, interruption and media-service notifications remain unconditional invalidators. Notification handlers may inspect Objective-C session state but never tear down the engine. Apple's [configuration-change notification documentation](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/avaudioengineconfigurationchange) warns that synchronous teardown from its internal queue can deadlock.

Voice processing can reference native NPC playback. Unity background music and effects use Unity's separate engine. **No guarantee is made that native processing cancels those signals.** Test music on/off and adjust the product mix based on measurements.

## Required build and device validation

The source and both `.h` header importers explicitly enable only iOS. `LLVoiceRing.h` uses the supported `.h` extension instead of `.hpp`. Unity documents automatic export for enabled native sources and `.h` files in its [iOS plugin integration manual](https://docs.unity3d.com/6000.0/Documentation/Manual/ios-native-plugin-automated-integration.html). The source importer requests `-fobjc-arc -fexceptions -fobjc-exceptions`, and declares AVFoundation/AudioToolbox dependencies. Exceptions are enabled for this file because its audio-engine cleanup uses `@try` while UnityFramework normally disables Objective-C exceptions. The first full-app build exposed that mismatch; standalone compilation had not reproduced Unity's target flags. Verify that the exported source entry retains all three flags, both headers, framework dependencies, C++17/iOS 17 settings and microphone usage description. The standalone test importer is disabled for Any, Editor and iOS; its main also requires LLVOICE_RING_TEST_MAIN. Confirm LLVoiceRingTests.cpp is absent from Xcode Compile Sources. Metadata text alone is not proof of successful import or compilation.

The standalone plugin and complete unsigned app compile/link checks passed. Next sign/install the exported Unity app, then test physical iPhones: permission denied and typed-only flows; speaker/headphone/HFP routes and unplugging; near/far speech and double talk; muted upload silence and stale-capture exclusion; route format changes; interruptions/media resets without deadlocks; repeated Start/Stop with callbacks in flight; backpressure and sustained streaming; consumed samples versus audible latency; and club music on/off. Measure echo reduction instead of inferring it from successful startup. Device checks remain pending.

Portable ring-only command: `clang++ -std=c++17 -O2 -DLLVOICE_RING_TEST_MAIN LLVoiceRingTests.cpp -o llvoice-ring-tests`. It checks wrap/full/empty, discard, epoch fencing, and one million concurrent samples. It does not test AVAudioEngine or microphone delivery.

The final incremental export passed `tools/check_ios_native_export.py`: native source bytes match the current source, both headers and all nine generated bindings exist, the source uses ARC, framework entries exist, the target uses iOS 17 and gnu++17, and the standalone test is excluded. The [packaging report](validation/ios-native/export-packaging.json) records exact exported hashes. The controller also passed its Editor audio-device regression (`audio-device-playmode-20260913-203108-744.xml`), which exercises the Unity playback path and local fixture, not native hardware. Portable ring and Apple SDK checks run in `.github/workflows/native-voice.yml`; both passed in the CI run above. Packaging and compilation do not establish device audio behavior.
