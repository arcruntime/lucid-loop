# Unity encounter integration guide

**Status:** Current implemented integration, reconciled against runtime source and the recorded [validation results](IMPLEMENTATION_VALIDATION.md). This replaces the earlier gym-only implementation plan. It is not a claim that final character presentation, Japanese speech, or physical iPhone acceptance is complete. The [technical design](TECHNICAL_DESIGN.md) defines the broader requirements; [DEMO_SCENARIO.md](DEMO_SCENARIO.md) identifies the authored implementation choices and their source status.

## Playable scene and component boundaries

The integrated scene is `Unity/Assets/Gyms/Scenes/BeforeTheDrop.unity`. `EncounterSceneBuilder` copies the club gym into that scene, removes the offline sample conversation controller, binds the investigator and four talkable NPCs, adds the non-interactable affair partner, and installs the encounter, voice, speech and presentation components. The shared build scene list enables `BeforeTheDrop`; the original gyms remain diagnostic scenes. Rebuilding a scene is an explicit Editor operation and must be coordinated with the artist and the owner of the open Editor.

| Implemented component | Responsibility and integration rule |
| --- | --- |
| [EncounterCoordinator](../Unity/Assets/Gyms/Runtime/Encounter/EncounterCoordinator.cs) | Creates/resumes the game connection, binds stable actor IDs, fences snapshot/world revisions, sends movement and approach intents, interpolates authoritative world positions and invalidates conversations on reset/disconnect. Resume credentials remain private process memory. |
| [EncounterClientState](../Unity/Assets/Gyms/Runtime/Encounter/EncounterClientState.cs) | Validates public snapshots and exposes detached state, actor actions, mood, phase, timer and retained discoveries. It does not decide game consequences. |
| [EncounterApproachIntent](../Unity/Assets/Gyms/Runtime/Encounter/EncounterApproachIntent.cs) | Tracks the selected NPC, loop and request sequence through approach, cancellation and authoritative eligibility. Manual movement, selection changes and reset must not accidentally open an old request. |
| [EncounterHud](../Unity/Assets/Gyms/Runtime/Encounter/EncounterHud.cs) and `EncounterHudLayout` | In-room selection, approach/talk feedback, history, typed replies, microphone toggle, leave, pause, rewind, timer and retained clues. Responsive layout and gesture cancellation are implemented; physical keyboard/safe-area acceptance remains separate. |
| [EncounterVoiceController](../Unity/Assets/Gyms/Runtime/Encounter/EncounterVoiceController.cs) | Owns one foreground Live session, typed submission, audio capture/playback, transcript and action-feedback events, generation fences and close/final-usage handling. | [EncounterSpeechBinding](../Unity/Assets/Gyms/Runtime/Encounter/EncounterSpeechBinding.cs) | Resolves the selected actor's `CharacterFaceDriver`, forwards generation-tagged output PCM and actual playback progress into the speech adapter, and clears speech on stop. `GymRoot` retains the project's hierarchy DI foundation and 30-fps request. Gyms has one-way references to `LucidLoop.LiveSpeech` and `LucidLoop.CharacterArt`; the artist runtime does not need a reverse dependency. Keep body and facial ownership in the artist's driver rather than adding competing graphs or direct blendshape writes from HUD/network code.

Mood strings are exactly `Intimate` and `Aggressive` throughout public snapshots and the coordinator event. The presenter now matches those values; lowercase comparisons previously prevented accepted transitions. Its PlayMode test feeds valid coordinator snapshots and verifies both track volumes and light transitions, as recorded in the validation ledger.

## Authoritative world, approach and loop behavior

[encounter-world.mjs](../server/src/encounter-world.mjs) owns the planar club geometry, obstacle-aware routes, player/NPC positions, recognition observations, conversation eligibility and physical encounter staging. The server advances movement and scenario time at 10 Hz with bounded catch-up; Unity interpolates accepted frames. This is a versioned approximation of the rendered club, not proof that every final mesh collider matches the plan. Keep the world manifest and scene geometry aligned when layout changes.

The client sends `game.walk` or `game.approach`, never an assertion that a character arrived or that violence occurred. The approach route is resolved server-side to a reachable speaking position; the client stays in overview until the corresponding authoritative result/eligibility allows conversation. The final `/live` gate still checks proximity and visibility. Stable IDs are `player`, `maya`, `ren`, `luca`, `theo`, and `affair_partner`; only the four named NPCs are talkable.

Accepted Maya wait/follow changes are persistent server behaviors. Waiting survives leaving the conversation; follow resumes only through an accepted action. Recording, Theo's approach, Luca's intervention and catastrophe remain distinct stages. Entering a zone alone does not kill an actor or grant victory. The current demo **does have an authored lethal outcome and resolution**: its scenario wrapper defines the shove/fall, mediated separation and end-of-set success. These are deliberate demo authoring choices documented in [DEMO_SCENARIO.md](DEMO_SCENARIO.md), not retroactive claims that the original Figma notes identified a victim or exact lethal action.

The implemented prevention path requires Intimate music, Luca's confirmed exposure information, Maya's private approach agreement, recognition, Theo's distance agreement, Maya stopping recording, the physical mediation group, and Luca's mediation. The server validates these prerequisites after interpretation. Foreground conversation pauses movement and scenario time; players must **Leave** for pending approaches/separation to execute. Waiting forever outside recognition is not victory.

Reset restores loop-local action, recognition, recording, mood, positions and scenario state while retaining intended player discoveries. Old-loop movement, approach, voice and interpretation work must be fenced. The server registry preserves same-game memory/history across reconnect within the process; it is bounded in-memory storage, not a durable save system across server restart or expiry.

## Game, text and voice data flow

The selected development setup is a local relay; use [IOS_LOCAL_RELAY.md](IOS_LOCAL_RELAY.md) for the phone/LAN address, access token and Development Build policy. A phone's loopback address is the phone itself. Keep the OpenAI key on the server. `/game` can run the world without a provider key, but live conversations and real model interpretation require the configured provider. Silent fixtures validate protocol handling, not character intelligence.

1. `/game` creates or resumes a game and streams safe snapshots/world frames. The public projection excludes canonical private facts and other NPC secrets.
2. A server-approved approach opens `/live` with the selected character and authenticated game credentials. The server attaches a fresh lease, builds filtered NPC context and same-loop history, and supplies its configured voice before conversation becomes ready.
3. **Typed replies are implemented.** `EncounterVoiceController.SendText` sends the application's `game.text` envelope. The relay/delegation interpreter supplies the supported provider interaction and strict action proposal path; it is not a made-up native `session.input_text` command. Typed-only entry does not require blanket microphone permission. Enabling the microphone requests permission separately.
4. Spoken requests are interpreted from explicit Live client delegation and relevant input evidence. A transcript pause or locally grouped caption is not an authoritative completed turn. Interpretation proposes bounded actions; server rules commit or reject them. Newer user evidence fences or reinterprets stale work according to the delegation contract.
5. `game.intent_result` reaches the conversation feedback adapter/HUD, so accepted, refused or clarification outcomes are not inferred from a plausible spoken promise. Committed state separately updates the world, clues and presentation.
6. Relevant context changes refresh the existing session through the implemented provider contract. Leaving, superseding, reset and device/suspension failures stop the old stream and invalidate its generation/lease. A reopened conversation reconstructs from server memory, not an indefinitely retained audio session.

The voice mapping remains server-owned: Maya `gleam`, Ren `quartz`, Luca `meridian`, Theo `vesper`. The exact provider events, bounded interpreter schema and configuration are documented in [server/README.md](../server/README.md) and implemented in `server/src`; do not replace them with generic Realtime examples from the original scratchpad.

`transcripts.mjs` stores ordered timed spoken fragments and explicit typed messages independently of the view. Same-speaker grouping is presentation only; it does not manufacture completed-turn events. Confirmed facts, NPC claims and raw dialogue remain distinct. Transcript `sessionId` now uses a separate non-authorizing conversation correlation ID; it must never contain the active lease bearer. History and interpreter context still require game/NPC/loop filtering.

The HUD uses scrollable bounded history and literal user/model text. Focused input must not also move the player; touch drag/cancellation, interaction state and approach cancellation have dedicated checks. Test keyboard appearance, Japanese glyph coverage and actual touch targets on the target phone before accepting them.

## Playback, English facial output and native iOS audio

There is now a real English acoustic producer: [EnglishSpeechStream](../Unity/Assets/LiveSpeech/Runtime/EnglishSpeechStream.cs) runs the pinned analyzer over mono 24-kHz PCM16 and keeps a bounded 15-weight target timeline. [LiveSpeechFaceAdapter](../Unity/Assets/LiveSpeech/Runtime/LiveSpeechFaceAdapter.cs) maps it into the artist's weighted `ApplySpeechFrame` API. Generation-tagged playback consumption drives pose timing; network receipt or transcript arrival is not the audible clock. Latency compensation, underrun, exhausted targets, speaker changes and stream reset must remain explicit.

Unity audio callbacks/native realtime callbacks must not mutate meshes or scene objects. Main-thread adapters apply the selected speech frame through `CharacterFaceDriver`, which retains ownership of speech/expression/contact composition, blink and gaze. `ApplySpeechFrame`, `ResetSpeech` and missing-target diagnostics now provide the weighted handoff the earlier plan requested. Existing `SetViseme`, `SetVisemes` and isolated `SetSpeechPose` APIs do not replace this live weighted path.

The iOS device backend is implemented in `IosNativeVoiceAudio` and `Plugins/iOS/LLVoice.*`: duplex native voice processing, bounded capture/output transport and playback telemetry integrate with `EncounterVoiceController`. Initial typed-only conversations retain Unity playback; native microphone ownership begins only after explicit permission. Device/route/suspension cleanup has controller tests. The [native audio guide](IOS_NATIVE_VOICE.md) records successful Apple SDK compilation/linking and export packaging. Neither that nor synthetic provider PCM establishes real echo reduction, capture quality, headset switching or interruption latency.

**Japanese remains unsupported by the accepted live producer.** The binding's language field is configuration, not language detection; unsupported Japanese produces a diagnostic without silently substituting English. Bilingual rig metadata and authoring/review sequences exist, but they do not prove Japanese acoustic contact timing or mixed-language playback. Follow [JAPANESE_SPEECH_PRODUCER.md](JAPANESE_SPEECH_PRODUCER.md) and [BILINGUAL_SPEECH_RIG.md](BILINGUAL_SPEECH_RIG.md) for the remaining producer, routing, glyph/font and face acceptance work.

## Character motion and presentation ownership

The artist's `CharacterFaceDriver` now supplies `PlayBodyMotion`/`StopBodyMotion`, composition with idle/expression gestures, final-pose handling and root ownership protections. Use that interface for reviewed clips instead of attaching a second Animator controller or competing PlayableGraph. World translation belongs to the authoritative movement adapter; clips must not drift the gameplay root. Keep two canonical skeletons, Ren on the female skeleton and her cap as a separate accessory.

The [animation handoff](../art/animation-handoff/README.md) contains 17 downloaded originals mapped to all 25 sheet rows, including reference-only rows and reuse warnings. File availability, Mixamo bone names and sheet Ready status do not establish retargeting or action suitability. Final recording, approach, intervention, fall and expressive conversation coverage still require artist-owned review. The currently verified primitive fall/phone presentations are intentionally limited placeholders.

## Validation and remaining gates

[IMPLEMENTATION_VALIDATION.md](IMPLEMENTATION_VALIDATION.md) is the evidence index, including exact CI runs, commits and local XML filenames. Recorded evidence now includes actual Unity encounter construction and PlayMode movement/catastrophe/reset captures; authoritative approach and phone-preview checks; character weighted speech/body tests; real-provider typed prevention, spoken requests and controlled spoken correction; iOS target activation/Xcode export; and native plugin Apple compilation. Those checks supersede the original statements that only gym fixtures existed. They are scoped evidence, not interchangeable proofs of full-device or production-art quality.

Repeat Editor tests through `GymValidation`'s scoped menus in a clean, idle shared Editor. Keep source/asset writes paused during PlayMode: an in-test script reload previously interrupted the TestRunner. Explicit integrated smoke tests require the real local relay and enabled `BeforeTheDrop` scene; provider tests are separately opt-in. Preserve the original gyms' navigation/audio fixtures as diagnostics. Check actual imported assembly, named test results and enabled build scenes, rather than a minimum pass count or manual Roslyn compilation alone.

Remaining acceptance includes the complete Unity app compiled/signed/installed through Xcode; physical iPhone 15 Plus LAN, microphone/AEC/headset/interruption behavior, thermal/memory and sustained 30-fps measurements; real keyboard/safe-area/touch behavior; accepted final character and music presentation; and a validated Japanese producer with playback-aligned expressive faces. Keep these gates visible while extending the already implemented encounter instead of treating it as either an untouched plan or a finished game.
