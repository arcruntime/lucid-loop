# Main-project blink and basic mouth review

The separate `RenDesignerBlinkReview` scene runs in **B:/lucid-loop/Unity**. Actual Unity 6000.3.24f1 MAIN Editor DX12 captures show independent left/right blink, partial/full closure, simultaneous mouth A=.5 plus blink, and reopening. This is a working basic-control prototype; likeness, eye silhouette, skin seams, oral paint and final style remain provisional.

Open `Unity/Assets/CharacterArt/Generated/Preview/Scenes/RenDesignerBlinkReview.unity` in the existing project Editor and enter Play. Blink L/R sliders and idle blink are available alongside the inherited mouth controls. The committed `RenDesignerMouthReview` scene is unchanged. No second Editor or external project is required. Shared-female rig calibration, gaze, full expressions and speech tracking are not supplied by this scene; its separate cap remains a temporary head-socket accessory.

`captures/` contains 28 actual 1536-square camera renders. The MP4 contains 150 actual 960-square Unity frames encoded at 30 fps for five seconds, with no audio. This deterministic output cadence is not a realtime/device performance measurement. `motion-contact.png` shows selected cropped frames for inspection. The 150 full PNG intermediates remain local; their exact hashes and actual weights are retained in `BlinkLiveEvidence.json`.

All 13 controlled layers use the same own-side weight for mesh blink and linear open/closed pigment. The new private meshes restore canonical Basis and position deltas at scale10000 under a compensating .0001 child. Actual save/unload/reload and65 BakeMesh samples passed the unchanged2e-6 native-space tolerance (maximum CPU error1.341104507e-7); no above-tolerance drawn moves remain lost. UVs, color endpoints, indices, base normals/tangents and imported shape normal/tangent deltas are preserved. This does not claim canonically authored deformation normals. Static blue iris/pupil/backings/highlights and current mouth bindings remain intact.

Rest and return-rest images are pixel-identical in front/quarter/profile. Motion frames0–27,35–45 and135–149 are exactly the same neutral image. Visual inspection of both closures/reopenings and the mixed mouth interval found no abrupt missing layers in the sampled contact. Existing far-eye fan fragments and boundary artifacts remain visible.

The zero-blink **same-geometry shader control is not byte-identical**:1155 lit pixels and1117 unlit pixels differ by at most1 color byte. Versus the previous actual MAIN mouth render, all1283 changed pixels lie in the eye region; only57 exceed1 byte and8 exceed8 bytes (maximum199 at a few high-contrast edge pixels). `main-neutral-eye-comparison.png` is an untouched native-pixel eye crop pair. Comparisons with older standalone captures are secondary because those used DX11; this MAIN run uses DX12.

`MainPreparationEvidence.json` is the original pre-GPU record and therefore retains its GPU_PENDING status. Actual completion is established by `BlinkLiveEvidence.json`, `live-verification.json`, the encoded clip and the sanitized completion log. No historical evidence hashes were rewritten. The earlier raw sparse-delta failure remains in `.local/ren-designer-blink-v1/attempt-01-*`, separate from this restored MAIN run.

For a fresh capture, enter Play in the prepared scene and run `Lucid Loop/Capture Ren blink review`. The output defaults to `.local/ren-main-blink-v1/live-review` and rejects a nonempty directory. To preserve an existing result, call `RenDesignerBlinkReview.BeginCapture` with a fresh B:/lucid-loop output directory from the already-open Editor. Preparation is a separate integration command and must not be rerun merely to capture. Native automation must reinitialize/enumerate Unity menus after Play's domain reload; stale native IDs did not dispatch the first capture attempts. Completion is identified by `REN_DESIGNER_BLINK_CAPTURE_OK`, not successful message posting. Play then exits and leaves the new scene accessible.

`main-dependency-manifest.json` records the exact main assets, metas, shader includes and resolved package GUIDs, distinguishing existing tracked dependencies from new required files. `executed-source/` preserves tested source bytes for evidence. To reproduce the original first preparation in a clean working checkout, place the retained `NeutralFrameAudit.json` at `.local/ren-blink-main-preparation-v1/ImportAudit.json` and use the frozen source export named by the builder; do not overwrite or regenerate already reviewed assets. This review uses a1x temporary render target without post-AA; the pipeline setting alone does not imply multisampled captures.
